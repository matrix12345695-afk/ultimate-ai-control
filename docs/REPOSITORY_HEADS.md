# Public repository branch freshness

ULTIMATE observes only main metadata for the two reviewed public repository identities:
NOVA WEB/nova-web-agency1426666605 and Kinder Spa/Kinder-Spa-android1427568609, owned by
matrix12345695-afk/250530390. Inventory and its Mini App remain excluded. This does not add
private-repository credentials, source execution, dependencies, writes or publication rights.

An explicit separate admission gate defaults disabled. Installation enables it only after
source/restore checks and adds two six-hour operations schedules. No hourly coding automation
is enabled. Schedule admission/advance and manual15-minute deduplication are transactional;
pause, emergency stop and disabled gates are respected. Unknown schedule definitions are not
overwritten. Late schedules enqueue one current check, not a backlog flood. /repo_head nova
or kinder queues a bounded check; /repo_heads displays stored metadata snapshots.

The worker issues GET to the fixed repository and git/ref/heads/main endpoints. IDs, owner,
public/nonfork identity, default branch, ref type and SHA are verified. Redirects, wrong
response destinations/encoding, oversized JSON and malformed refs fail closed. Bodies use
bounded read1 chunks with a12-second inter-read deadline and3-second socket timeouts; the
existing30-second job alarm also covers stalled DNS/transport. No token is sent or stored.
Only normalized metadata, enum errors and hashes enter the journal; arbitrary remote text
and descriptions are discarded. This is a read-time GitHub snapshot, not production version
verification or a promise that the branch cannot move immediately afterward.

New heads do not advance pinned source/CI versions. A new SHA is reported as untested; a
matching SHA does not run tests or verify deployment. Immutable report/hash, project cache,
transition notice and terminal job event commit under the lease/current emergency epoch.
Network/identity failures are failed jobs with durable unknown-state evidence. Independent
work continues. Out-of-order observations are retained but cannot replace the current cache
or open/close notices. Unchanged heads/errors do not send repeated notices. Initial matching
snapshots are quiet; installation sends one consolidated receipt after both real jobs finish.
Scope incidents are resolved only by a later valid observation and only when their original
job/report/notice belong to this monitor. Existing owner decisions are never resolved here.

Typed memory binds repository observations to their job/project/report/result; corrupt results
are not promoted and do not stall the memory cursor. Reads are side-effect free. Metadata
older than12 hours is marked stale. The original pinned-file registry remains unchanged and
has its own /repo_check tests; stage7 stays active because other projects and execution/change
preparation are still incomplete.

Rollback disables only this feature gate/two recognized schedules and cancels only its queued
metadata jobs before restoring the preceding worker/calendar/voice-aware app. Immutable
reports/memory, existing schedules, private policies, costs and owner pause/emergency state
remain. No live DB restore, unrelated service action or code/DB change in managed projects.

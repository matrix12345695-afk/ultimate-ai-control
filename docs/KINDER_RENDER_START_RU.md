# Kinder Spa: готовая форма создания Worker в Render

Подготовка кода выполнена в Kinder [PR #6](https://github.com/matrix12345695-afk/Kinder-Spa-android/pull/6).
Новая ветка только для создания Worker: `kinder-render-inspection-20261029`.
Ожидаемый коммит: `6bce0cc67572575e7abb06d380f7fc0906ddd08b`.
Программный код совпадает с проверенным `c5aa4dc9`: изменены только корневой
файл развёртывания и инструкция, рабочая ветка приложения сохранена.
Всё размещение Kinder — только Render. На VPS ничего устанавливать не нужно.

Подключённый инструмент Render не умеет создавать Worker или Blueprint.
Поэтому один раз потребуется создание через панель самого Render. После этого
его состояние и безопасные результаты проверки можно читать через подключение.

1. [Открой готовую форму Render](https://render.com/deploy?repo=https://github.com/matrix12345695-afk/Kinder-Spa-android/tree/kinder-render-inspection-20261029). Репозиторий, отдельная ветка и файл уже указаны ссылкой.
2. Выбери **My Workspace** аккаунта matrix12345695@gmail.com.
3. Проверь: только **kinder-spa-telegram**, Background Worker, Frankfurt,
   один экземпляр 0.5c-512mb, **$7/месяц**, затем подтверди создание в Render.
   Этот дополнительный расход уже согласован ответом «Продолжай». Новая база,
   диск, Redis, Cron и изменения других сервисов не предусмотрены.

Открытие ссылки само по себе не создаёт платный ресурс; это форма проверки и
подтверждения у провайдера. Создать Worker через подключённый инструмент нельзя,
поэтому этот последний шаг выполняется в панели Render.

**Токен сейчас вводить не потребуется.** Render сам свяжет существующую
`kinder-spa-db` с отдельным ключом подключения только для обследования.
Пароль базы или токен нельзя присылать в чат. GitHub Secret остаётся непрочитанным.

Начальный режим — `inspection`: процесс один раз проверит структуру и права
базы только на чтение, затем будет ждать. Он не запускает Telegram, не читает
его токен, не создаёт таблицы, клиентов, роли или пароли и не меняет данные.
Само создание Worker оплачивается даже в таком режиме. Статус Running в Render
будет означать работающий процесс обследования, а не готовность бота.

После создания напиши **«Создал»**. Название и ID сервиса можно найти через
подключение; секреты в чат не нужны. Далее будут проверены настоящий коммит,
внутреннее TLS-соединение и отчёт о структуре/правах. Затем можно подготовить
точные изменения и отдельную рабочую роль, убрать временное операторское
подключение и настроить бот через защищённые поля Render Environment.

Публикация клиентской версии, миграции, изменение прав и включение настоящего
бота этим шагом не выполняются. API/админка остаются отдельным предложением в ветке feature/render-api-pilot.
Ветка kinder-render-inspection-20261029 предназначена только для этой формы
Worker; сливать её в основную рабочую ветку не нужно.

Инструкция также доставлена существующим Ultimate AI Control: уведомление183,
Telegram425,28 октября2026 в20:30 по Ташкенту. Это сообщение центра управления,
а не подтверждение запуска нового Kinder-бота. Статус создания Worker остаётся
«ожидает действия владельца».
